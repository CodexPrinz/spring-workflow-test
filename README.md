# Student API

A Spring Boot REST API for managing students, backed by PostgreSQL.

## Run

Copy `.env.example` to `.env`, set a private `DB_PASSWORD`, and start PostgreSQL:

```sh
cp .env.example .env
docker compose up -d
```

Then start the application:

```sh
./mvnw spring-boot:run
```

The Compose service reads the database name, username, password, and host port from `.env`; `.env` is excluded from version control. The application reads `DB_URL`, `DB_USERNAME`, and `DB_PASSWORD` from the same file. Hibernate updates the `students` table on startup, including adding the `date_of_birth` and `nationality` columns. Those columns remain nullable for existing records; create and update requests require both values.

Formatted SQL statements and bound JDBC parameter values are logged. Student service operations log their start and completion, including elapsed time in milliseconds. Actuator health, info, and metrics are available under `/actuator` (for example, `/actuator/health` and `/actuator/metrics`). The `/actuator/info` endpoint includes the packaged application version under `build.version`.

Swagger UI is available at `/swagger-ui/index.html`, and the OpenAPI specification is available at `/v3/api-docs`. Each student endpoint includes a brief description in the generated API documentation.

The student directory is available at `/` when the Spring Boot application is running. It provides a green-themed interface for listing, searching, adding, editing, and deleting student records.

## Endpoints

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/api/students` | List all students |
| `GET` | `/api/students/{id}` | Find a student by ID |
| `GET` | `/api/students/name/{name}` | Find a student by name |
| `POST` | `/api/students` | Add a student |
| `PUT` | `/api/students/{id}` | Edit a student |
| `DELETE` | `/api/students/{id}` | Delete a student |

POST and PUT accept `{"name":"Ada Lovelace","email":"ada@example.com","dateOfBirth":"1815-12-10","nationality":"United Kingdom"}`. The date of birth must be an ISO-8601 date in the past; nationality must be selected from the country list. Responses include the generated `id`, `name`, `email`, `dateOfBirth`, `nationality`, `createdAt`, and `updatedAt`; request and response DTOs are documented as separate Swagger schemas. Audit timestamps are generated by the application, with `createdAt` preserved on edits. Email addresses must be unique. Errors use a consistent JSON shape with status, message, request path, timestamp, and any validation errors.

Student names are sanitized to plain text on write and in responses to prevent stored HTML from being rendered as executable markup.

## Tests

Run `./mvnw test` to execute isolated unit tests. Mockito mocks the service dependencies, repository, and servlet request; the unit tests do not connect to PostgreSQL or start a Spring application context.
